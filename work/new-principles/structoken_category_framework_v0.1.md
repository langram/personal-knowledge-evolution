# Structoken 范畴论假设框架（v0.1）

> 用途：作为 Structoken / Compact-IR 项目的理论性假设框架，帮助把“连续 embedding 空间 vs 离散 DAG 结构”的张力翻译成一组可检验的范畴论对象、函子与近似交换图。
>
> 状态：工作假设，不是定理集。它的价值在于组织后续 probe、干预和算法设计，而不是提前宣称已被证明。

---

## 0. 一句话摘要

本项目最深的张力，不应被表述为“DAG 如何映到欧氏空间中的点”，而应被表述为：

**一个结构化程序对象中的三类不变量——偏序/包含、组合/构造、上下文中的动态演化——分别以何种方式被送入表示系统。**

因此，最贴切的理论框架不是单一函子

\[
F : \mathrm{DAG} \to \mathbf{Vect}
\]

而是一个**分解后再表示**的多路框架：

\[
\mathcal G_{\mathrm{prog}}
\xrightarrow{U}
\mathcal P_{\mathrm{reach}}
\times
\mathcal O_{\mathrm{ops}}
\times
\mathcal K_{\mathrm{ctx}}
\xrightarrow{(F_{\mathrm{ord}}, F_{\mathrm{comp}}, F_{\mathrm{ctx}})}
\mathcal H_{\mathrm{ordgeom}}
\times
\mathcal R_{\mathrm{rep}}
\times
\mathcal E_{\mathrm{fib}}
\]

其中：

- `U`：把程序 DAG 分解成“可达偏序 + 操作组合 + 上下文/层推进”
- `F_ord`：表达祖先/后代/包含如何被几何化
- `F_comp`：表达父节点如何由子节点组合出来
- `F_ctx`：表达同一节点如何随层、前缀、mask、readout 而变化

---

## 1. 背景：这个框架试图解释什么

Structoken 当前最重要的经验事实可以压缩成一句话：

- **静态 probe 弱**：最终或单层的节点表示，不一定保留强的可线性读出的 DAG 几何
- **动态 probe 强**：层更新或局部计算过程，对真实 DAG 邻接存在显著敏感性

这意味着：

1. 结构可能**不主要存放在对象（nodes as points）中**
2. 结构可能主要存放在**态射（updates / flows / reindexings）中**
3. tokenization 的作用不只是压缩，还可能是在选择一个**结构忘却函子**的强弱

因此，理论框架必须能同时容纳：

- 静态几何表示
- 组合式生成语义
- 被上下文索引的动态表示

---

## 2. 基本对象：从程序 DAG 到范畴

本框架默认研究对象是一个程序依赖结构，例如 SSA / Merkle-DAG / AST-DAG / dataflow DAG。

记该结构为：

\[
G = (V, E, \mathrm{op}, \mathrm{attr})
\]

其中：

- `V`：节点（寄存器定义、表达式、子 DAG 根等）
- `E`：有向依赖边
- `op(v)`：节点的操作符或构造标签
- `attr(v)`：其他属性，如类型、常量、位置、span、hash、是否 merge 等

### 2.1 路径范畴 `Path(G)`

最细的范畴化方式是路径范畴：

- 对象：节点 `v ∈ V`
- 态射：从 `u` 到 `v` 的有向路径
- 复合：路径拼接
- 恒等：长度为 0 的空路径

它保留了“信息沿依赖链传播”的可复合结构。

### 2.2 可达性薄范畴 `Reach(G)`

把“存在路径”压缩成真假：

\[
u \preceq v \iff u \leadsto v
\]

得到一个偏序，等价于一个薄范畴（任意两对象之间至多一个态射）。

这个对象特别适合表达：

- 祖先 / 后代
- 蕴含 / 被蕴含
- 父节点包含子 DAG
- 节点间的可比较性 / 不可比较性

### 2.3 操作范畴 / 操作 operad `Ops(G)`

如果只保留边，我们会丢掉“父由哪些子、以什么操作组合而成”的语义。

因此引入一个更贴近程序语义的对象：

- 对象：类型、值域或中间表示的 sort
- 多元态射：操作符实例，如
  - `add : X ⊗ Y → Z`
  - `phi : X₁ ⊗ ... ⊗ X_k → X`
  - `hash_join : H₁ ⊗ ... ⊗ H_k → H`
- 复合：由表达式 / 子图嵌套给出

这一步把“父子边”提升成“有 arity 的构造态射”。

### 2.4 上下文范畴 `Ctx`

这是解释“静态弱 / 动态强”所必需的一步。

定义一个上下文范畴，表示模型内部的视角变化：

- 对象：上下文状态 `k`
  - 当前层 `l`
  - 当前 token 前缀 `≤ i`
  - 当前可见域 / attention mask
  - 当前 readout 方案（open / close / span / instruction-span 等）
- 态射：上下文扩展
  - 层推进 `l → l+1`
  - 前缀扩展 `i → i+1`
  - mask 调整
  - readout 切换

这意味着“节点表示”天然是**被上下文索引的**，而不是上下文无关的单点对象。

## 3. 目标侧：表示不是单一的 `Vect`

### 3.1 偏序几何范畴 `OrdGeom`

用于承载祖先/包含/可达等非对称关系。对象可以是：

- 锥体（cones）
- 盒子（boxes）
- 双曲球面区域
- 带非对称包含关系的区域对象

它的重点不是“点距离”，而是：

- 包含
- 可比性
- 非对称邻域
- join / overlap

### 3.2 表示范畴 `Rep`

用于承载组合/构造。对象可以是：

- 向量空间
- 张量空间
- 模块化表示对象
- 带参数化态射的表示对象

态射不必限于严格线性映射，也可以是可学习、可组合的近似算子。

### 3.3 纤维化表示范畴 `FibRep`

令

\[
p : \mathcal E \to \mathcal K
\]

是一个纤维化结构，其中：

- `K = Ctx`
- 每个 fiber `E_k` 是上下文 `k` 下的表示空间
- 同一抽象节点 `u` 不再对应一个固定向量，而对应一个截面：

\[
s_u : \mathcal K \to \mathcal E
\]

即 `u` 在每个上下文 `k` 下都有一个表示 `s_u(k)`。

这一步是整个框架的关键：

> 结构可以主要存在于 fiber 之间的重索引 / 推进态射中，
> 而不必显著存在于任一单独 fiber 的静态点几何里。

## 4. 三类核心函子

## 4.1 `F_ord : Reach(G) → OrdGeom`

### 目的
把 DAG 的偏序/包含结构映到非对称几何对象上。

### 希望保留的不变量

- `u ≼ v`（祖先/后代）
- `u` 与 `v` 是否可比
- siblings 是否通常不可比
- merge 节点是否体现某种 join

### 典型理想形式

存在一个区域对象 `C(u)` 或 `B(u)`，使得：

\[
u \preceq v \Rightarrow F_{\mathrm{ord}}(v) \subseteq F_{\mathrm{ord}}(u)
\]

或者更弱地：

\[
\mathrm{score}_{\mathrm{ord}}(u,v)
\text{ 在 } u \preceq v \text{ 时显著更高}
\]

### 对应直觉

- 父节点不是一个点，而是一个“覆盖子结构的区域”
- 兄弟节点未必接近，但可能同处于父区域下
- DAG 上的蕴含更像包含关系，而不是对称相似度

---

## 4.2 `F_comp : Ops(G) → Rep`

### 目的
把“父由子节点通过操作组合出来”的语义，映到表示范畴中的组合态射。

### 关键点
这通常不是严格函子，而更像一个 **lax monoidal functor**。

也就是说，不期待严格满足：

\[
F(x \otimes y) = F(x) \otimes F(y)
\]

而只期待存在可学习、近似成立的组合态射：

\[
F_{\mathrm{comp}}(\mathrm{op}(c_1,\dots,c_k))
\approx
\Phi_{\mathrm{op}}(F(c_1),\dots,F(c_k))
\]

### 对应直觉

- `add`、`phi`、`hash_join` 不只是边，而是不同的组合规则
- 父节点表示是否能由孩子表示与操作符共同预测，成为核心问题
- 如果这条更成立，真正该设计的是组合器，而不是 pairwise bias

---

## 4.3 `F_ctx : Ctx → FibRep`

### 目的
表达“同一节点在不同层、不同前缀、不同 readout 下如何变化”。

### 基本形式
令 `k ∈ Ctx`，则节点 `u` 在 `k` 下的表示写作：

\[
F_k(u) \in \mathcal E_k
\]

对任何上下文推进 `\alpha : k \to k'`，存在重索引 / 推进态射：

\[
T_\alpha : \mathcal E_k \to \mathcal E_{k'}
\]

于是可以问某种**近似自然性**是否成立：

\[
T_\alpha(F_k(u)) \approx F_{k'}(u)
\]

进一步，对结构态射 `f : u → v`，可问：

\[
T_\alpha \circ F_k(f)
\approx
F_{k'}(f) \circ T_\alpha
\]

### 对应直觉

- “静态表示弱”并不意味着“结构不存在”
- 结构可能主要体现在层更新、prefix 扩展、mask 变化下的态射中
- 动态 probe 的正结果，正好暗示应研究 `F_ctx` 的态射性质，而不仅是某个 `F_k(u)` 的点几何

## 5. 忘却函子：为什么 tokenizer 是理论对象，而不只是工程细节

当前项目最重要的理论启发之一是：

**tokenizer 的本质，不只是压缩，而是选择一个忘却函子的强弱。**

记原始程序对象范畴为 `ProgStruct`，序列对象范畴为 `Seq`，则 tokenization 可视为：

\[
W : \mathrm{ProgStruct} \to \mathrm{Seq}
\]

这个 `W` 会忘掉一部分结构，典型如：

- 节点边界
- 共享子图
- 显式祖先/后代关系
- arity 与组合语义
- ref / merge 的对齐线索

### 在项目语言中的直觉

- L1：更强的忘却。很多节点边界、引用关系、组合规则被压平到普通 token 序列里。
- L3：更弱的忘却。节点、引用、子树边界更显式，模型中间层更容易恢复或利用这些结构。

因此，tokenizer 不只是“前处理”；它决定了后续表示函子和动态态射是否还有机会接近某些结构不变量。

## 6. 为什么“图到度量空间的函子”不应被当成唯一主角

许多 probe 默认的思想是：

\[
F_{\mathrm{metric}} : G \to (X, d)
\]

使图距离或树距离在某个空间中被近似为欧氏距离、余弦、范数等。

这在方法上很有用，但在本框架中只应被视为一个**投影视角**，而不是本体。

原因：

1. DAG 中最重要的关系常常是**非对称**的，普通度量是对称的。
2. 父节点代表的是**子结构**，更像区域或组合结果，不像单点。
3. 动态计算中的结构未必体现在最终点几何上。

因此，更合理的定位是：

- `F_metric`：用于 probe 和局部近似
- `F_ord` / `F_comp` / `F_ctx`：更接近本体层面的结构保持映射

---

## 7. 近似交换图：本项目不应追求“严格保结构”，而应追求“lax 保结构”

大模型几乎不可能是严格函子。更合理的理论语言是：

- **lax monoidal functor**
- **近似自然变换**
- **带误差项的交换图**

这意味着，很多实验中的“残差”不再只是噪音，而是理论对象的一部分。

### 7.1 组合的 lax 性

\[
F(\mathrm{op}(c_1,\dots,c_k))
\approx
\Phi_{\mathrm{op}}(F(c_1),\dots,F(c_k))
\]

误差项反映：

- 上下文影响
- 序列化带来的额外信息
- 任务驱动下的压缩

### 7.2 自然性的 lax 性

\[
T_{k \to k'}(F_k(u)) \approx F_{k'}(u)
\]

误差项反映：

- 层更新不是纯结构推进，也混有任务相关压缩
- mask 与 readout 会扭曲等价关系
- 序列顺序引入额外方向性

## 8. 对 Structoken 当前结果的理论重述

把 v0.2 的经验发现翻译成这个框架的语言，可以得到：

### 8.1 关于静态弱

静态 probe 弱，不等于“模型没学结构”；更可能意味着：

- `F_metric` 的某个欧氏投影弱
- 但 `F_ord` 或 `F_ctx` 仍然存在
- 结构主要活在态射中，而非最终对象点几何中

### 8.2 关于动态强

动态 probe 强，更接近说明：

- 某些 `Ctx` 推进态射中存在真实 DAG 邻接相关的增量项
- 这些项可被视为 `F_ctx` 中的局部自然性 / 近似消息传递行为
- L3 可能不是“让对象更有结构”，而是“让某些态射更接近真实结构推进”

### 8.3 关于 tokenizer

L3 的优势不一定是“更好表示”，而可能是：

- `W_L3` 比 `W_L1` 忘却得更少
- 因此后续 `F_ord / F_comp / F_ctx` 更容易对齐到真实结构

这也解释了为什么：

- 静态几何改进不明显
- 动态结构敏感性却显著增强

## 9. 核心工作假设（供后续实验反复检验）

### H1. 偏序假设
程序 DAG 的祖先/后代关系，在表示系统中更适合被看成**非对称包含/锥体关系**，而不是对称点距离。

### H2. 区域假设
节点的语义对象更接近“区域 / 子空间 / 子结构摘要”，而非单点。

### H3. 组合假设
父节点的表示主要通过某种操作相关的组合态射近似生成。

### H4. 动态优先假设
结构主要体现在上下文推进态射中，而非静态对象表示中。

### H5. 忘却强弱假设
L1 与 L3 的差异，本质上是忘却函子强弱不同，而不只是词表大小不同。

### H6. lax 保结构假设
模型不严格保结构，但某些交换图在统计上近似成立，且这种近似度可以被 probe 测量。

### H7. tree-vs-DAG 假设
模型中一部分信号只对应“树状括号组合”，另一部分才对应真正的“共享子图 / DAG 关系”；两者必须被拆开测量。

### H8. readout 相对性假设
节点表示不是绝对对象，而依赖 readout 方案；不公平的 readout 会把“结构被学到”与“后验信息被读到”混为一谈。

## 10. 从理论到实验的翻译表

| 理论对象 | 在项目中的对应 | 最自然的 probe / 干预 |
|---|---|---|
| `Reach(G)` | ancestor / descendant / comparable / siblings | order / cone / box probe |
| `Ops(G)` | add / phi / hash_join / merge / subtree combine | composition probe |
| `Ctx` | layer, prefix, mask, readout | dynamic / naturality probe |
| 忘却函子 `W` | L1 vs L3 tokenizer / serialization | tokenizer 对照实验 |
| lax monoidal 性 | 父 ≈ op(孩子) | parent reconstruction |
| 近似自然性 | 层间更新、prefix 扩展 | commuting-diagram style probe |

## 11. 当前框架下最需要警惕的理论误区

### 11.1 把“点距离”误当成本体
如果一个 probe 只测欧氏距离，很可能错过偏序、包含、区域语义。

### 11.2 把“有结构 signal”误当成“有严格对象表示”
动态态射里有结构，不等于最终表示一定强可读。

### 11.3 把 tokenizer 视为纯工程变量
它可能直接决定了后续结构是否还能被模型恢复。

### 11.4 把所有 DAG 信号都当成同一种东西
至少要区分：

- 偏序
- 组合
- 上下文推进
- 树括号组合 vs 真 DAG 共享节点

## 12. 后续研究问题（理论版）

1. 是否存在一个比欧氏点空间更自然的节点语义对象，例如 box / cone / affine subspace？
2. `F_comp` 更像函数式语义、operad 映射，还是某种图代数表示？
3. `Ctx` 是否应细分为层范畴、前缀范畴、mask 范畴、readout 范畴？
4. “静态弱 / 动态强”是否意味着模型真正学到的是**态射语义**而非对象语义？
5. 不同 tokenizer 是否可被比较为不同的忘却函子，进而形成一个“忘却强度”层级？
6. 可以否把 probe 的残差系统化解释为 lax 性，而不是纯误差？

---

## 13. 给项目的实际指引

如果接受本框架，那么 Structoken 的后续研究重心应从：

- “有没有一个万能 embedding 函子把 DAG 映成点”

转向：

- 哪些不变量最值得保留
- 它们分别落在哪类目标范畴
- 现有模型主要在对象层还是态射层保结构
- tokenizer 改变的是哪个忘却函子
- 哪些 probe 能分别对应偏序、组合、自然性

也就是说，后续最自然的工作不是继续堆新的全局 bias，而是：

1. 先分辨结构种类
2. 再测每种结构住在哪一层、哪种 readout、哪种动态态射里
3. 再做对准该结构不变量的定向干预

## 14. 建议的文档迭代方式

这份文档建议按如下方式更新：

- `v0.1`：提出对象、函子、假设词典
- `v0.2`：根据 probe 结果删掉不支持的假设，强化被数据支持的分量
- `v0.3`：把被验证较强的部分收缩成更精确的理论图式和近似交换图

更新原则：

- 优先删掉过强的说法
- 把“失败”记录成对对象/函子的排除证据
- 把“成功但弱”记录成局部近似，而不是整体定理

---

## 15. 结语

这个框架最想表达的不是“范畴论可以神奇地解释一切”，而是：

> 连续表示与离散结构之间的张力，往往来自我们试图用**单一对象层语言**去描述一个本质上同时包含**偏序、组合、上下文推进、忘却**的系统。

范畴论在这里最有价值的作用，是逼迫我们问清楚：

- 结构在哪里
- 哪些态射在起作用
- 哪些信息被忘掉了
- 哪些交换图只是在近似成立

对 Structoken 而言，这种问法本身就已经是研究增量。
