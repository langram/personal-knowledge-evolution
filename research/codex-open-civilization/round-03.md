# 第三轮　从个人资料库生长出能够共同学习的组织

前两轮留下了一个更清楚的方向：让知识能够广泛流动，让人能够实际选择合作方式，让执行能力与明确的授权、资源和责任相连。在这个方向上，新制度不必先等到一个理解全部世界的智能诞生，也不必先要求所有人变得完全理性。它可以从一个人已经需要的服务开始，逐步把共同学习的能力做出来。

本轮给出的是Codex提出的暂定方案。它没有自动成为作者的观点，也没有被写入《新原理》的正文。已经运行的只有本文明确标出的合成程序；其余组织安排是供讨论和后续试验的设计。

## 一、把起点从统一管理改为共同增加能力

我建议用这样一个问题判断最初的制度是否有价值：一个普通人加入以后，是否更容易保存自己的经历，表达尚不成熟的想法，找到能够接力的人，完成自己独力完成不了的事情，并且在不满意时保有实际离开的能力？

这个问题把文明的进步落实到了参与者能够使用的能力。公共知识增长不是收集更多文件本身；智能增长也不是某个控制中心看得更多本身。它们应该表现为更多人能够理解、创造、协作和修正错误。如果系统收集了海量数据，却让参与者更难理解规则、更难改变服务，那么它可能只扩大了管理能力。

因此，我提出三个相互连接但不必由同一个组织独占的组成部分。

个人资料与代理节点保存本人能够控制的记录、偏好、授权和任务。有限的服务共同体提供备份、计算、共同研究或设备维护。公共知识层保存可公开的规则、证据、知识产品与试验结果。一个人可以同时使用几个服务共同体，公共知识也可以被没有加入这些共同体的人使用。

这并不要求一开始制造新硬件、新操作系统和新语言。最小版本可以利用现有存储、加密、版本管理和人工检查，把资料恢复、规则说明和任务接力做可靠。新的Merkle-DAG语言与运行时若能够减少协作中的重复解释、提高验证和迁移能力，可以逐步替换相应部分；是否替换，应由具体收益决定。

## 二、让一粒想法获得一条可以接力的生长路径

一个人想到数学上的某个联系，往往并不知道它是否早已有之，也不知道下一步应该学习什么。他可以选择独自研究几年，也可能因为无法判断价值而放弃。作者设想的全球智能网络，应当首先改善这种处境。

我建议把“发表一个成熟结论”之前的过程也变成可协作的对象。提出者先保存自己真正想到的内容，并选择公开、有限分享或暂时私存。个人AI帮助整理问题、检索可能的已有结果、区分直觉与已经成立的步骤，但每一项补充都注明来源，不把AI补全的严密表达倒写成提出者最初已经完成的工作。

随后形成一份很小的接力记录：现在的问题是什么，已有证据是什么，尝试过什么，卡在哪一步，下一个能够独立验证的小任务是什么。数学问题可能需要一个反例搜索、一个特殊情形的证明或一次定义澄清；软件问题可能需要最小复现和一个兼容性检查；社会方案可能需要测量某个真实成本。

别人不必一次承担整个宏大问题，只需接住自己擅长的一步。贡献记忆把这些步骤连接起来：最初的直觉、找出的先例、失败的尝试、补充的证明和后来的实现，都有可核查的位置。若两个人独立想到同一件事，保留两条来源，再在相同结论处汇合，不必抹去其中一方。

这里最值得改变的，是“只有成果足够成熟才值得被看见”的门槛。早期想法不需要假装成熟，但应能获得与其成熟程度相称的帮助。它的价值可以在后续过程中显现，而不是由一个起初并不了解它的评分器一次性决定。

这需要资源安排。我建议从可用于探索的资源中划出一个事先约定的小额度通道，允许新参与者、冷门问题和少数意见获得有限试验机会。具体采用轮换、抽签、同行提议还是组合方式，应在小范围比较，不能预先宣布动态权重一定最好。探索额度不依赖已有名望，但每次使用仍须说明做了什么、学到了什么，并接受范围和总量约束。

所谓失败也应细分。试验否定一个清楚的猜想，可能为后人节省大量工作；未完成却没有留下可复用信息，则是另一种结果。承认负结果不等于为随意制造失败发奖励，而是让排除错误路径的工作能够被看见。

## 三、贡献、需要与共同投入各自回答不同的问题

第一轮提出的分账在这里进一步明确。

贡献记录回答“哪些工作怎样帮助了后来的工作”。需要与保障安排回答“在现有资源下，哪些生活和参与条件需要优先满足”。共同投入记录回答“为了未来的服务和研究，为什么把多少资源放在这里”。它们有关联，却不能互相冒充。

例如，一个人为公共备份系统修复了严重错误，这项贡献应当被准确记住；但这不自动给予他查看别人备份的权限。另一个人因为身体条件需要更多辅助资源，这项需要不应被解释为贡献较少的道德缺陷。某个项目得到更多设备，是对一项可检查计划的投入，也不应变成项目负责人的永久统治资格。

人们仍然需要讨论分配原则。算法可以展示不同规则会产生什么结果，检查规则是否被一致执行，并揭示被忽略的代价；它不能把“我们重视什么”伪装成完全没有价值选择的技术结论。

一种可能的早期做法是先公开服务成本与最低保障承诺，再讨论维护、探索和扩张的额度。参与者可以只购买或使用服务，也可以参与劳动、研究和共同建设；不能因为不愿投入额外劳动就剥夺其已经约定的数据控制权。更多出资可以记录为有边界的资源贡献，不自动兑换为对其他参与者更多的基本支配权。

这些是制度建议，尚未证明长期财政可持续。尤其在资源不足时，需求不能凭记录自动得到满足。方案必须显示缺口、等待顺序、可替代方案和停止扩张的条件，而不是用“智能优化”隐藏短缺。

## 四、异议可以成为另一条受限的试验路径

新制度若只允许一个最终答案，讨论仍会迅速变成争夺谁有权定义正确。我的建议是：把事实分歧、目标分歧和资源冲突分开处理。

事实分歧如果能设计低风险试验，就让竞争解释提出可比较的预期，保存共同认可的观察办法。目标分歧则不一定通过更多事实就会消失；有人重视便利，有人重视独处，可以在能够分离的服务中保留不同选择。资源确实不能同时满足两个计划时，再明确讨论取舍，而不是把落选者说成认知不够先进。

对于少数意见，可以在不侵害他人权益、不转嫁成本的范围内保留一个有限探索通道。这样，提出异议的人有机会把主张变成证据，多数人也不必立即承担整个社会的改造风险。若试验有效，其他分支可以采用；若失败，保留其条件与反例，而不是把失败者永久排除出讨论。

有些问题不能这样分开。例如共同设备的安全、无法隔离的环境影响和不能中断的照护责任，需要更大范围的安排。可分叉制度因此是有条件的多样性，不是任何人都能用“这是我的分支”为影响他人开脱。

动态权重在这个结构中主要服务于具体判断：谁对这一类问题的预测较可靠，哪些证据值得优先复核。它不替代平等的参与资格，也不把专业优势扩大成普遍的隐私权、处置权或分配权。

## 五、行动怎样从建议变成可以承担后果的执行

我建议把共同动作的过程分为提出、检查、预留、执行、观察、结算和学习。分开这些步骤，是为了让每一步的责任可以说明，而不是要求人们手动完成大量手续。简单重复动作可以自动完成；复杂或不可逆动作需要更充分的判断。

提出阶段说明任务、证据与预期效果。检查阶段确认该动作是否在被允许的范围内，所需授权是否仍然有效。预留阶段为它锁定确实存在的资源。执行阶段通过能够限制实际作用的接口进行。观察和结算比较预期与结果，再把可复用的经验送回知识层。

可作为下一步软件接口草案的字段包括：

| 字段 | 它必须回答的问题 |
|---|---|
| 任务与内容引用 | 本次到底要做什么，采用哪个版本？ |
| 委托人、执行者与受影响范围 | 谁可以委托，谁实际执行，可能影响谁？ |
| 授权版本、有效期与取得方式 | 依据的授权是否适用于此刻、此事和此范围？ |
| 资源单位、额度与预留凭据 | 使用什么资源，是否已经被其他动作承诺？ |
| 允许的外部作用 | 执行接口到底允许产生哪些变化？ |
| 请求身份、停止与恢复条件 | 重试如何处理，谁可以停止，能恢复到哪里？ |
| 观察记录与责任安排 | 由谁检查效果，偏离预期时怎样处置？ |

这只是接口设计，当前实验没有实现签名、网络授权、可信硬件或真实资源预留。把这些字段写进JSON本身不会产生相应能力；执行器必须确实服从约束，授权来源必须能被检验，观察不能只相信执行者的自我报告。

对于资源协调，有两种值得比较的起步方式。小型在线服务可以把某份资源的预留集中到一个清楚、可替换、可审计的状态更新入口。需要离线工作时，可以把总额度预先分成互不重叠的份额，节点只能使用自己的份额。前者需要在线协调，后者可能留下暂时无法利用的闲置资源。分散并不意味着没有协调成本，而是选择在哪个环节支付它。

授权撤销也是如此。一个完全离线的节点不可能凭空知道刚刚发生在别处的撤销。可以选择联网确认、短期授权、较小的离线额度或停止离线执行。具体选择取决于行为后果，不能用“不可篡改”承诺无法提供的即时性。

## 六、这一轮实际检验了哪一个小结论

第二轮的两个独立节点各自拿到完整10单位预算，会合计使用12。本轮把它改为固定、不重叠的局部额度：左节点得到q，右节点得到10−q。

[实验预先说明](experiment/quota-pre-registration.json)先固定了检验范围，然后程序穷举q从0到10、两个请求分别从0到11的全部1,584种组合。每个节点仍使用第二轮未经修改的C，真实效果由合成输入给定。全局检查重新相加接受动作的效果。

结果是1,584种组合中没有出现总量超过10；共进行3,168次局部接纳调用、17,688个计数的检查操作组。额度6与4、申请6与4的正例能够用完10单位。这支持一个有限结论：在实验条件下，不重叠的局部额度能保持这一个共享资源上限。[完整结果](experiment/run-03/summary.json)

其数学理由也可以直接写出。设总上限为B，节点额度为q₁……qₙ，满足所有qᵢ非负且Σqᵢ≤B。若每个节点的累计真实用量sᵢ通过原子局部更新始终满足0≤sᵢ≤qᵢ，那么Σsᵢ≤Σqᵢ≤B。对一个节点，初始sᵢ=0；只在sᵢ+a≤qᵢ时接受非负增量a，拒绝时不改变sᵢ，由归纳得到局部不变量。

这是一个基本的不变量论证，不是本研究发现的新数学定理。它把条件摆在了结论前面：额度不能重复发行，局部更新不能竞态失序，用量必须对应真实效果，转移额度不能使旧额度与新额度同时可用。实验只枚举两个节点各一个请求的有限情形；归纳论证则在所述条件下解释连续局部动作。真实系统是否满足这些条件，还需要另外验证。

本轮同时保留了两个不漂亮的结果。第一，左6右4时，如果只有左边申请7，系统会拒绝，尽管全局还有10单位。这是分割额度的利用率代价，需要安全的重新分配或等待协调来改善。第二，同一个请求编号在两边各执行一次，仍可能保持资源上限却重复完成同一件事。因此，额度保护不等于全局唯一执行。

处理重复执行可以要求某类请求归属于明确的执行入口、支持操作幂等，或者建立额外的协调记录；这些办法各有适用条件，本轮没有实现并验证它们。也没有实现额度发行和转移协议、真实网络、即时撤销或影响预测。保留这些空白，才能知道下一次工程工作到底需要补什么。

Merkle-DAG在这里的作用，是让方案、输入、失败、修订和规则版本可引用、可核查。资源约束本身不需要DAG才能成立。下一步若比较存储实现，应使用同样的行为要求，把普通数据库作为基线，再考察跨组织核验、历史恢复与迁移是否带来足够收益。

## 七、从个人数据主权起步的最小服务

最初不必记录全部生活，也不必建立一个全新的社会。已有的个人知识库已经提供一个实际起点：历史会话、个人文章、来源、编辑过程和理论关系。可以先把这一种服务做成别人愿意使用、自己也能持续负担的产品。

我建议最小服务只承诺五件事：能够导入本人合法取得并愿意保存的资料；保留原件与整理结果的关系；按本人选择控制访问；能够完整导出并在另一处恢复；能够从一次错误整理或错误升级中退回。公开贡献与私人备份使用不同范围，不能因为使用同一种DAG格式就默认全部公开。

最初的系统可以完全由个人操作。AI帮助整理、查找和提出关系，但不能静默改写原话。另一个独立程序检查文件是否完整、恢复是否一致、授权范围是否被遵守。这里的“独立”指检查路径与被检查的功能有所区分，不意味着更换一个模型名称就自动获得独立性。

在此基础上，再提出一个轻量的知识接力功能：本人从资料库中选择一个已经适合分享的问题，产生公开版本、证据范围和下一步任务。别人可以在不读取整个人生档案的情况下参与。这把个人数据主权与公共知识增长接了起来，而不是在两者之间二选一。

如果有人只需要备份服务，可以只使用备份；愿意投入更多的人可以参加维护、讨论和研究。服务必须先在当前阶段有价值，不能要求普通用户为了一个遥远的文明目标忍受眼前不可靠的工具。

## 八、按证据进入下一阶段，而不按宣传规模推进

下面是建议的后续路线，本次没有自动开始真实部署、招募、收费、录像或资源购买。

| 阶段 | 可以交付的东西 | 进入下一阶段前的检查 | 不通过时的处理 |
|---|---|---|---|
| 个人起点 | 一种资料类型的导入、原件保留、导出恢复、有限分享 | 换一处空目录可恢复；故意损坏的资料能被发现；整理错误可回退 | 修复这一条链，不增加数据种类 |
| 小组影子试验 | 少量自愿参与者的任务接力与规则比较；建议不直接改变真实资源 | 与等权、轮换及明确责任人方案比较；检查新手和少数意见是否被系统性忽略 | 保留失败记录，简化规则或放弃加权 |
| 有限真实服务 | 明确额度、成本和退出安排的备份或计算服务 | 真实恢复演练、授权撤销检查、维护者不协助迁移、成本覆盖说明 | 限制规模，停止新增承诺，先维持已约定服务 |
| 分支互通 | 两个独立维护的实现交换资料、知识产品和规则版本 | 不共享控制账户仍能迁移；冲突与重复请求被识别；共有责任可结算 | 保留各自运行，暂不扩大互相依赖 |

个人起点的下一次验收可以事先选取30份已授权的代表性资料，再加入10份故意损坏、缺失或版本冲突的合成样例。这些数字只是建议的初始试验规模，不是足够覆盖现实的统计保证。检查应同时包含成功恢复、准确报告失败，以及没有把未知内容当成完整恢复。

小组试验需要先记录各方案的判断目标与资源条件，不因看到结果后再改评价标准。动态权重若在准确性、参与负担或对新手的机会分配上没有优势，就不采用。用户能够理解和维护的简单规则，本身是一种制度能力。

资源成本也要完整记录：存储、带宽、计算、人工维护、故障恢复、用户迁移和必要储备。模型文件的复制便宜不等于提供智能服务免费，开放的软件也不等于运维劳动消失。成本下降应当体现为参与者得到的实际服务改善，不能只是把劳动转移到不可见的志愿者身上。

## 九、制度本身也应当积累可复用的知识

软件项目保留一个修复，不只为了说明作者曾经努力过，而是为了让后人不必重复同一个错误。制度也可以保留同样有用的材料：某项规则在什么条件下被采用，预期解决什么问题，参与者怎样理解它，实际出现什么后果，为什么修改或停止。

我建议每次制度试验留下一个能够复用的小包：规则版本、采用条件、预先评价标准、经过适当授权的观察、反例、成本和下一版选择。公共层不需要收进参与者全部私人生活，却需要避免只展示成功指标。别人可以比较适用条件相近的试验，而不是凭某个组织声望直接复制整套规则。

这为作者所说的文明智能提供了一种具体生长方式：各个共同体不必先被一个中心统一，仍可以通过公共的失败与改进记录共同学习。知识的传播让后来者少走弯路，智能工具让寻找类似问题、检查条件和组织接力更加容易。若这样的学习确实降低重复劳动与协作成本，就有理由扩大；若没有，就检查究竟是记录方式、激励安排还是问题本身不适合。

这里不预设制度演化必然单向走向某一种唯一形态。不同生活方式可能长期并存。新机制的优越性应体现在能让人获得更好的实际选择和更高质量的合作，而不是靠宣布自己代表必然未来来免除比较。

## 十、三轮之后，哪些结论可以留下

值得保留的中心提案是：用可控制的个人资料、可接力的知识任务、范围明确的共同服务和能够实际迁移的规则分支，逐步构成相互学习的网络。它把个人数据主权、公共知识与集体行动接在一起，却不要求先把全部权力集中到一个全能算法。

已经得到的有限技术结果是：逐项合法不足以保证组合合法；共享额度需要协调或保守分割；真实效果和现行授权是额外条件；分割额度能在所述模型中保持上限，但会牺牲部分即时利用率，也没有解决全局重复执行。这些正反结果已经保存，可以成为下一次实现的验收材料。

尚未得到的，是人类参与者长期合作更稳定、资源分配更公平、经济上可持续、知识创新更快以及大规模组织能够可靠运行的实证结论。它们应当进入后续研究计划，而不应写成已经被程序证明。

我认为这个构想最值得投入的地方，是它允许把宏大目标拆成当下有用、能够失败、能够退出、能够继续改进的具体服务。每完成一个真实的小循环，文明设想就多获得一块可以独立站立的基础。三轮探索在这里结束；后续是否采用其中某个方向，由作者依据这些材料选择。
