## 已达成的规则

权威格式是 [PKST 0.1/N3.1](protocol/PKST-0.1.md)，双方接受收据在 [consensus.json](protocol/consensus.json)。文件保留当时的候选标题以保持哈希不变，后来的接受状态由收据记录。Gemini 适配规则及澄清另见 [gemini-consensus.json](protocol/gemini-consensus.json)。

档案分三层：

1. **原件与事件**：原始 ZIP、JSON、JSONL 等按原始字节保存；正文按原字符保存。每次发言有独立事件身份、来源、角色、原生时间与取证坐标。同一句话出现在不同会话中，不会因此成为同一发言。
2. **思想与关系**：概念、论断、问题、假设、引用和要求分别记录。每个提取结果带原话证据及整理者。相似文本仅形成关联候选；不能直接证明原创、复制方向、因果或用户赞同。
3. **版本与视图**：修改产生新对象，旧对象保留；快照有父快照。思想修订与档案整理分开。思维导图和时间线是可重建视图，能切换主题、关系类型、事件截止时间和整理截止时间。

原始 bytes 使用 raw CID，结构对象使用规范 DAG-CBOR + CIDv1 + SHA-256。CAR 可以打包大量对象，SQLite 只作可重建索引。内容哈希证明字节身份，不证明思想正确或作者归属。

**两种图不能混淆**：内容对象的引用依赖和快照父图必须无环；概念之间的支持、反驳等语义关系可以有环。树状思维导图只是某个视角，不强迫一个想法只能属于一个上级主题。

**两种时间分开**：某句话的原生时间，与 AI 何时把它整理入库分别保存。回复没有独立时间时保持未知，不能把提问时间直接借给回复，也不能把后来形成的理论倒填到最早出现相关词语的日期。

**身份与立场分开**：来源中的 user/human 通道不能单独证明是本人输入；AI 可以通过 Computer Use 在该通道发送协调消息。作者、说话通道、观点持有者、引用者、整理者分别保留；用户本人确认以新 assessment 记录，不改写原始发言。
