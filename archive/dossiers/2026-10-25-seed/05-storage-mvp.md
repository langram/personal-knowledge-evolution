# 从个人数据主权开始的最小存储方案

首个使用者为发起人。先让本人稳定地保存、找到、恢复和迁移已有资料，再考虑对他人提供服务。本稿设计部署与验收步骤；没有购买服务器、创建收费账户、配置密钥或启动后台服务。

## 第一项可交付服务

用 Windows 作为目前资料汇集与检索端，Mac 作为独立读取与恢复端。原件、PKST 对象和可重建索引分开保存。第一批恢复样本控制为不超过 1 GiB、至少 100 个文件，覆盖中文名、空文件、长文件名、同名不同内容、JSONL、图片和目录结构。先用非敏感夹具，再加入本人选定资料。

初步服务目标是：本地查询不依赖原聊天平台；每日生成一次可恢复版本；在第二设备的新目录中两小时内恢复该 1 GiB 样本；恢复后的路径、文件数、字节数和内容哈希全部一致。24 小时恢复点目标与两小时恢复时间都是待测试目标，不是已经提供的保证。扩展到 10 GiB 或全库时重新测量网络与耗时。

## 两步落地

**第一步是零新增订阅的个人备份闭环。** 优先利用已拥有的设备和仍有足够配额的个人 OneDrive。客户端使用成熟的加密版本备份工具 restic，通过 rclone 连接云端。两者的官方文档支持这一组合及 OneDrive 后端。新建独立仓库路径，不能把正在运行的备份仓库放在 OneDrive 桌面同步目录中让两个客户端同时管理。[restic 仓库文档](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html) · [rclone OneDrive 文档](https://rclone.org/onedrive/)

这一阶段仍租借商业存储作为底层资源，迁移与恢复能力由个人掌握；它是自管服务的前置验证。现有 OneDrive 已收到的历史传输包不会因该方案而自动加密或被删除。

**第二步是由自己运营的文件服务。** 若确实需要浏览器文件访问、分享和跨设备日常同步，再部署最小 Nextcloud 实例，最初只开启文件相关功能。考虑一台 Linux 实例，试验配置可从 2 vCPU、4 GiB 内存、约 40 GB 系统盘另加数据空间开始；这是待压测的设计预算，不是官方承诺或适用于所有配置的最低值。部署时固定经过核验的版本及镜像摘要，并记录恢复流程。[Nextcloud AIO 官方项目](https://github.com/nextcloud/all-in-one)

## 私人数据与协作文件

| 类型 | 保存与访问 | 首期边界 |
| --- | --- | --- |
| 私人原始会话与作品 | 本地明文按现有设备保护；上传前由备份客户端加密 | 云端不存明文搜索索引；初期密钥由本人保管 |
| 经本人选择的协作文件 | 可放入自管 Nextcloud，按文件夹授权 | 明确管理员是否能够读取；敏感库不默认开放在线预览 |
| 公共知识与项目文稿 | 经确认后发布独立副本 | 发布原件摘要不等于发布原始私密会话 |
| 秘密及恢复材料 | 独立保存并另做离线恢复准备 | 不放进公开 Git 仓库、任务日志、屏幕录像或同一个云端账户 |

Nextcloud 服务器端加密的密钥在服务器侧，不能据此承诺管理员无法读取。客户端端到端加密适用于相应需求，但要另外验证其客户端和工作流能力。首期敏感材料采用客户端加密备份，避免把服务器端加密误作私人空间保障。[Nextcloud 加密说明](https://docs.nextcloud.com/server/latest/admin_manual/configuration_files/encryption_configuration.html)

## 构造选择

| 候选 | 解决什么 | 起步代价 | 决定 |
| --- | --- | --- | --- |
| 立即部署完整协作平台 | 浏览器访问、账户和共享 | 运维、升级、数据库和暴露面较多 | 第二步按需求启用 |
| 文件复制与哈希清单 | 最快建立可读副本 | 缺少成熟版本、加密与备份管理 | 仅作验收基线 |
| restic 与 rclone，加现有 PKST | 版本恢复、加密云副本、来源关系 | 需验证密钥恢复、网络及仓库维护 | 首期采用的设计路线 |

PKST 不承担文件系统同步或加密职责。备份工具不承担思想语义合并。SQLite 索引可以重建，原件与对象不能只剩数据库中的记录。双方工具保持清楚边界，减少重复实现。

## 操作顺序与验收

| 步骤 | 动作 | 通过标准 |
| --- | --- | --- |
| 1 盘点 | 列出白名单资料、总量、来源缺口；核实磁盘和云端配额 | 不把尚未取得的 ChatGPT 官方导出算入已备份内容 |
| 2 固定输入 | 对活动 JSONL 取固定前缀，复制到本轮暂存；记录字节截止点 | 归档过程中源文件继续追加不影响已固定输入 |
| 3 本地初始化 | 从官方渠道固定工具版本和校验值；本人设置仓库口令 | 能用独立保存的恢复材料重新打开仓库 |
| 4 云端样本 | 通过本人完成的账户授权写入专用备份路径 | 样本备份结束，完整读取检查通过 |
| 5 第二设备恢复 | Mac 在新目录按快照 ID 恢复，再反向抽查 Windows | 全部样本哈希、相对路径、数量和字节数一致 |
| 6 退出演练 | 暂不使用原聊天平台及同步客户端，从恢复材料读取资料 | 仍能找回文件并重建选定 PKST 查询 |
| 7 故障演练 | 在独立夹具中模拟错误口令、缺块及本地误删 | 错误明确报告，旧版本可恢复，不覆盖唯一副本 |
| 8 扩展 | 按实际容量扩大范围，记录上传与维护成本 | 首次全量校验后才登记新恢复范围 |

restic 的恢复目标目录应为新目录；恢复指令与完整读取检查参考官方文档。[恢复文档](https://restic.readthedocs.io/en/stable/050_restore.html) · [仓库检查](https://restic.readthedocs.io/en/stable/045_working_with_repos.html)

以下仅为部署时的命令模板，远程名称尚未配置，当前没有执行：

```powershell
# 先通过 rclone config 由本人完成专用 remote 的账户授权。
restic -r "rclone:seed-remote:seed-vault" init
restic -r "rclone:seed-remote:seed-vault" backup "C:\已固定的样本目录"
restic -r "rclone:seed-remote:seed-vault" snapshots
restic -r "rclone:seed-remote:seed-vault" check --read-data
# 使用实际核对过的快照 ID，在另一设备恢复到新目录。
restic -r "rclone:seed-remote:seed-vault" restore SNAPSHOT_ID --target "C:\新的恢复目录"
```

第一轮不自动清理旧版本。恢复成功、保留期和容量成本明确之后，再单独设计保留策略。同步完成提示、云端显示文件名、哈希根存在，均不能代替完整恢复验收。

## 成本与预算

首轮新增订阅预算设为 0；这里指利用已有付费或免费配额，已有订阅、电力、网络与维护时间仍计入总成本。新付费服务须先形成具体容量与地域报价，再由本人决定。

作为可替换对象存储的价格参照，2026 年 10 月 25 日读取的 Backblaze B2 官方页面标示 6.95 美元每 TB 每月，免费出站额度为平均存储量的三倍，超出部分 0.01 美元每 GB。仅作公开报价例子，不表示已经选定供应商或地域。[官方价格](https://www.backblaze.com/cloud-storage/pricing)

按十进制容量、仅存储、不考虑税费与优惠：10 GB 约 0.0695 美元/月，100 GB 约 0.695 美元/月，1 TB 约 6.95 美元/月。真实备份量还包括历史版本与索引；两份各 100 GB 的独立计费副本，存储项约为 1.39 美元/月。VPS、域名、流量、支持和劳动另计。不能把存储项宣传为完整服务售价。

月度现金成本记作：固定服务＋存储单价×平均实际存储量＋超额出站＋其他实际费用。总成本再加维护工时、设备折旧及失败恢复成本。恢复样本和单位成本有记录后，再决定是否购买硬件。

## 首期能够与尚不能提供的东西

首期目标是一个人可持续使用的数据保存与恢复服务，附带公开规则和成本记录。它不包括多用户生产 SLA、全设备容灾、私人数据云端智能搜索、自动代表本人进行公共决策或完整 AGI。第二位试用者加入前，应增加账户隔离、本人密钥恢复、退出演练和明确的支持责任。
